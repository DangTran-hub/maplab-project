# Field Reports REST API

## Overview

This document defines the initial JSON REST contract for field reports. All paths are rooted at `/api`; requests and responses use `application/json`. The contract covers reading reports and creating one report. It does not define authentication, updates, or deletion.

## Report resource

The existing sample model is in `src/data/sampleReports.js`. Its fields and observed types are:

| Field | Type | Create requirement | Notes |
| --- | --- | --- | --- |
| `id` | string | Server-generated | Stable identifier; format is not defined by the existing model. |
| `title` | string | Required | Must contain non-whitespace text. |
| `description` | string | Required | Must contain non-whitespace text. |
| `category` | string | Required | One of `start`, `landmark`, `end` (the values present in sample data). |
| `latitude` | number | Required | Decimal degrees. |
| `longitude` | number | Required | Decimal degrees. |
| `imageUrl` | string or `null` | Optional | Omission and `null` both mean no image. |
| `status` | string | Server-generated | The only observed value is `PENDING`; no other statuses are established. |
| `createdAt` | string | Server-generated | ISO 8601 timestamp in UTC. |

The sample data is the only existing source for the model; it does not formally define optional fields or enum registries. The required fields and nullable/optional behavior above are proposals based on that shape.

## Endpoints

### List reports

- **Method and URL:** `GET /api/reports`
- **Purpose:** Return all reports.
- **Parameters:** None. No pagination or filtering is defined.
- **Success:** `200 OK`, with a JSON array of report objects. An empty collection is `200 OK` with `[]`.
- **Authorization:** No authentication is defined in the current project. This contract assumes access is permitted to the calling application; revisit before production.

Example response:

```json
[
  {
    "id": "poi-1",
    "title": "Điểm A",
    "description": "Điểm bắt đầu khảo sát",
    "category": "start",
    "latitude": 21.0051,
    "longitude": 105.8432,
    "imageUrl": null,
    "status": "PENDING",
    "createdAt": "2026-10-23T00:00:00.000Z"
  }
]
```

### Get a report

- **Method and URL:** `GET /api/reports/{id}`
- **Purpose:** Return one report by its ID. The braces indicate a path parameter; they are not sent literally.
- **Path parameter:** `id` — the report identifier string.
- **Success:** `200 OK`, with the report object as the response body.
- **Not found:** `404 Not Found` when no report has that ID.

Example response (`200 OK`):

```json
{
  "id": "poi-1",
  "title": "Điểm A",
  "description": "Điểm bắt đầu khảo sát",
  "category": "start",
  "latitude": 21.0051,
  "longitude": 105.8432,
  "imageUrl": null,
  "status": "PENDING",
  "createdAt": "2026-10-23T00:00:00.000Z"
}
```

### Create a report

- **Method and URL:** `POST /api/reports`
- **Purpose:** Create a report.
- **Request content type:** `application/json`
- **Success:** `201 Created`, with the created report object in the response body.
- **Generated by the server:** `id`, `status` (`PENDING`), and `createdAt` (current server time in UTC). Clients must not supply these fields.
- **Authorization:** Same assumption as the list endpoint; authentication is out of scope.

Required request fields are `title`, `description`, `category`, `latitude`, and `longitude`. `imageUrl` is optional and may be `null`.

Example request:

```json
{
  "title": "Điểm D",
  "description": "Cột mốc khảo sát",
  "category": "landmark",
  "latitude": 21.0062,
  "longitude": 105.8445,
  "imageUrl": null
}
```

Example response (`201 Created`):

```json
{
  "id": "poi-4",
  "title": "Điểm D",
  "description": "Cột mốc khảo sát",
  "category": "landmark",
  "latitude": 21.0062,
  "longitude": 105.8445,
  "imageUrl": null,
  "status": "PENDING",
  "createdAt": "2026-10-23T13:02:48.567Z"
}
```

The ID and timestamp in this example are illustrative.

## Validation

- `title` and `description` must be strings containing at least one non-whitespace character.
- `category` must be exactly `start`, `landmark`, or `end` (case-sensitive).
- `latitude` must be a finite JSON number from `-90` to `90`, inclusive.
- `longitude` must be a finite JSON number from `-180` to `180`, inclusive.
- `imageUrl` may be omitted or `null`. If a string is supplied, it must be an absolute `http` or `https` URL. This URL constraint is a proposal because the existing examples only show `null`.
- `id`, `status`, and `createdAt` are server-generated on create and are not accepted as client-supplied fields.
- `status` on returned reports must be `PENDING`, the only status in the existing sample model. Additional status values must be agreed before being introduced.
- A malformed JSON body or a request that fails field validation returns `400 Bad Request`.
- No further business rules (for example, uniqueness, content length, or coordinate precision) are defined here.

## Error responses

All errors use this JSON shape:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The request is invalid.",
    "details": [
      {
        "field": "latitude",
        "message": "Must be a number between -90 and 90."
      }
    ]
  }
}
```

`details` is included for validation failures and omitted when it does not apply. Error messages and codes are safe for clients; internal implementation details and database errors must not be exposed.

| HTTP status | Code | Use |
| --- | --- | --- |
| `400 Bad Request` | `VALIDATION_ERROR` | Invalid or missing fields; `details` identifies field-level validation failures. |
| `400 Bad Request` | `INVALID_JSON` | The request body is not valid JSON. |
| `404 Not Found` | `REPORT_NOT_FOUND` | The requested report ID does not exist. |
| `500 Internal Server Error` | `INTERNAL_ERROR` | Unexpected server failure; return a generic message without internal details. |

Example not-found response:

```json
{
  "error": {
    "code": "REPORT_NOT_FOUND",
    "message": "Report not found."
  }
}
```

Example server-error response:

```json
{
  "error": {
    "code": "INTERNAL_ERROR",
    "message": "An unexpected error occurred."
  }
}
```

## Assumptions and decisions to revisit

- The project has sample report objects but no separate formal schema. Required text fields, `imageUrl` optionality, and its URL validation are proposed for this contract.
- The category values come directly from the three sample reports. `PENDING` is the only established status; agree on any additional lifecycle values before implementation.
- The format and generation strategy for `id` are unspecified. The server must return it as a string.
- No authentication or authorization policy exists yet; define one before exposing the API beyond its intended trusted clients.
- Pagination is intentionally omitted for the initial contract. Revisit if report volumes require it.
